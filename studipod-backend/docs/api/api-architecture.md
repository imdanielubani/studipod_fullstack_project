# API architecture

## Shape

| Aspect        | Decision                                                                                                       |
| ------------- | -------------------------------------------------------------------------------------------------------------- |
| Style         | REST over HTTPS, JSON bodies                                                                                   |
| Base path     | `/api/v1` (`API_PREFIX` + URI versioning, `API_VERSION`)                                                       |
| Candidate API | `/api/v1/*` (used by the webapp)                                                                               |
| Admin API     | `/api/v1/admin/*` (used by the admin dashboard only; separate guard, audience and audit trail)                 |
| Webhooks      | `/api/v1/payments/webhooks/stripe`, `/api/v1/video-sessions/webhooks/livekit`, `/api/v1/email/webhooks/resend` |
| Health        | `/api/v1/health/live` (process up), `/api/v1/health/ready` (PostgreSQL and Valkey reachable)                   |
| Documentation | OpenAPI 3 generated by `@nestjs/swagger`, UI at `/api/docs` when `SWAGGER_ENABLED=true`                        |
| Naming        | Plural kebab-case resources (`/study-preferences`), camelCase JSON fields, ISO 8601 UTC timestamps             |
| IDs           | UUIDv7 strings (time-ordered, index-friendly, not guessable as sequential integers)                            |

## Response envelope

Successful responses:

```json
{ "data": { "id": "0193…", "status": "confirmed" } }
```

Collections add pagination metadata:

```json
{
  "data": [ … ],
  "meta": { "limit": 20, "nextCursor": "eyJpZCI6…", "hasMore": true }
}
```

Errors use one shape everywhere (produced by a global exception filter):

```json
{
  "error": {
    "code": "BOOKING_SLOT_UNAVAILABLE",
    "message": "This time slot is no longer available.",
    "details": [{ "field": "startsAt", "issue": "conflict" }],
    "requestId": "c1f2…"
  }
}
```

- `code` is a stable, documented machine-readable string; clients branch on it, not on `message`.
- `5xx` responses never include stack traces, SQL or vendor error text.

## Pagination, filtering, sorting

- **Cursor pagination** by default (`?limit=20&cursor=…`): stable under inserts and fast on large tables. Maximum `limit` is 100.
- Offset pagination (`?page=&pageSize=`) only for admin tables that need page numbers.
- Filtering via explicit query parameters (`?examinationId=&subjectId=`), never a free-form query language.
- Sorting via an allowlisted `?sort=createdAt:desc`.

## Bootstrap order (when implemented in `main.ts`)

1. Fastify adapter with `trustProxy` from `TRUST_PROXY`, body size limit, request ID generation.
2. `@fastify/helmet` (security headers; see [security standards](../security/security-standards.md#http-security-headers)).
3. CORS with the exact origin allowlist from `CORS_ALLOWED_ORIGINS`, `credentials: true`.
4. `@fastify/cookie` with `COOKIE_SECRET` (refresh-token cookie).
5. Global `ValidationPipe` (`whitelist`, `forbidNonWhitelisted`, `transform`).
6. Global exception filter (error envelope) and logging interceptor (`nestjs-pino`).
7. Global `ThrottlerGuard` backed by Valkey, with stricter limits on authentication routes.
8. URI versioning and global prefix.
9. OpenAPI document (only when `SWAGGER_ENABLED=true`).
10. `enableShutdownHooks()` so in-flight requests finish on deploy.

## Idempotency and webhooks

- `POST` endpoints that create payments or bookings accept an `Idempotency-Key` header; keys are stored in Valkey for 24 hours.
- Webhooks verify the provider signature on the **raw** body before parsing, record the provider event ID, and ignore duplicates. Processing is handed to a queue so the provider gets a fast `2xx`.

## Contract for the clients

- The OpenAPI document is the contract. A typed client generated from it is planned for the webapp and admin dashboard.
- Breaking changes go to `/api/v2`; `v1` keeps working until both clients have migrated.
